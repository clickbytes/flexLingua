# flexLingua · Interlingua CORE + Batch A v1.18 (PL/EN)

Static **meaning-first** language-engine prototype. Source text is parsed into a language-independent semantic representation; target text is generated by grammar rules and lexicon entries stored as JSON. No backend, LLM, bundler, CDN, sentence-pair phrasebook, or runtime dependencies.

> This is **not** a general-purpose translator. It deliberately handles a restricted Polish and English grammars, plus a legacy Turkish adapter so that the design can be validated without hiding semantic gaps behind heuristics.

## Current direction — PL ↔ INTER ↔ EN (A1–C2)

**Current scope:** Polish ↔ language-independent CORE/INTER ↔ English, starting with controlled A1 coverage and expanding step by step through A2, B1, B2, C1 and C2. **There is no CEFR C3.** The project is currently a controlled-language prototype, **not** a fully A1-compliant translator. Its older Turkish adapter is out of scope for this roadmap.

- **[Project roadmap](ROADMAP.md)** — Oxford 3000/5000 as *reference* vocabulary coverage, CEFR stages, quality gates and the later plan for a conversational engine with configurable personality.
- **[Development and documentation workflow](docs/development-workflow.md)** — architecture rules, mandatory verification, version/release discipline and documentation updates in the same change.
- **[Documentation index](docs/README.md)** — technical specifications, history, run instructions and in-progress work.
- **[Batch B question translation](docs/questions-v1.19-pl-en.md)** — controlled PL/EN question parsing and generation implemented in source; **v1.19 release remains in progress**.

**Documentation policy:** every completed language feature needs tests, honest coverage/limitations, and synchronized docs. The future conversational personality and knowledge-research capabilities are not yet implemented. [Known documentation/repository discrepancies](docs/repository-audit.md) are explicitly tracked until resolved.

## Studio GUI — tłumacz, słownik i INTER Explorer

Interfejs `flexLingua Studio` ma cztery zakładki: **Tłumaczenie**, **Słownik i odmiany**, **INTER Explorer** oraz **Pokrycie reguł**. W słowniku wybiera się jawnie polski lub angielski i wpisuje lemat bądź znaną odmienioną formę (np. `koty`, `children`). GUI wyświetla **wszystkie aktualnie zadeklarowane odmiany**, jasno informuje o braku hasła (*Not found in dictionary*) lub paradygmatu i zachowuje narzędzia zaawansowane. Wizualizacja INTER pokazuje strukturę ostatniego tłumaczenia. Dodano domyślnie wyłączoną opcję **eksperymentalnego stosowania istniejących paradygmatów do słów spoza słownika**. Użytkownik musi wybrać schemat i temat fleksyjny; może odfiltrować schematy po części mowy, obejrzeć hasła referencyjne z rzeczywistego słownika, zobaczyć brakujące komórki i ostrzeżenia o niezgodności formy podstawowej oraz skopiować hipotezy. Wynik jest oznaczony jako hipoteza, a nie potwierdzona odmiana. Można **porównać dwa ręcznie wybrane paradygmaty tej samej części mowy** (bez automatycznego wyboru poprawnego). ## Run locally through loopback HTTP

[Instrukcja uruchomienia na Windows po polsku](docs/uruchomienie-lokalne.md).

The UI requires a local HTTP server. Direct `file://` opening is unsupported because browsers block ES modules and JSON requests from local files.

- **Windows:** double-click `start.bat` in the repository root. It starts a loopback-only server, then opens the browser. Node.js is preferred; if unavailable, Python is used. Close the console to stop the server.
- **Any platform (Node 20+):** `npm run dev`, then open `http://127.0.0.1:8000/`.
- **Any platform (Python):** `python -m http.server 8000 --bind 127.0.0.1`, then open `http://127.0.0.1:8000/`.

After changing source, run the project checks:

```sh
npm test                  # Node 20+; no npm install necessary
# browser contract suite: http://127.0.0.1:8000/tests/index.html
```

GitHub Pages and other static HTTP hosts use the native module + JSON version. For Windows, run `git pull`, then start `start.bat`; close its console to stop the local server. Historical references to a second `odmiana` page are tracked as a [repository/documentation gap](docs/repository-audit.md), since those files are not present in the current branch.

## PERS-02 — explicit PL/EN subject pronouns

- Polish `ja, ty, my, wy` and English `I, you, we` map to a versioned CORE deictic referent (`speaker` or `addressee`) plus separate grammatical `person` and `number`. No speaker/addressee entities or gender are inferred.
- Controlled present clauses round-trip through PL ↔ CORE ↔ EN. English `you` keeps singular and plural readings; Polish realization exposes both `Ty` and `Wy` as alternatives.
- First/second-person pronouns stay separate from third-person `he/she/on/ona` anaphora. Cross-turn identity without an explicit session identity is refused as `UNRESOLVED_DEIXIS`.
- The current scope does not include object pronouns or Polish first/second-person past-tense forms. See the [PERS-02 contract and examples](docs/pers02-deictic-pronouns.md).

This is still controlled-language analysis and generation, not arbitrary Polish or English. There is no zero-subject Polish parsing, complex person-based complement agreement, or new productive language package beyond PL/EN. Turkish stays legacy-compatible.

The previously referenced `docs/person-future-v1.14.md` is **not currently tracked**; verify historical claims against code and tests.

## v1.12 — curated PL/EN lexicon expansion and external gold tests

The next increment scales the *existing* language packages rather than inventing a second translator. It adds 14 parallel PL/EN noun lexemes connected to CORE (including the two senses of `mouse/mysz`), 16 ontology entries and four reusable paradigm classes. There are **no stored inflection tables** on the new noun records: forms are generated from stems, inherited paradigms and explicit JSON exceptions.

Polish coverage now includes the seven cases in both singular and plural **for these 14 reviewed nouns**. English covers singular/plural, including `city/cities`, `mouse/mice`, `woman/women`. The manually authored oracle in `tests/fixtures/gold-nouns-v1.12.json` checks **224 expected surface cells** and their inverse analyses, independently of the rule implementation. In addition, tests generate controlled sentences using each new CORE concept.

```sh
npm run check:gold        # checked reference forms + inverse + CORE mappings
npm run check:release     # all earlier validations and Node regressions
```

Older adapters without morphology retain existing vocabulary and now skip the *new* lexemes lacking explicit form tables instead of failing at registration. To parse or realize the new lemmas, register PL/EN morphology. These expansions are hand-curated reference data, **not** a licensed third-party dictionary import. See [v1.12 data contract and examples](docs/lexicon-v1.12.md). Do not mistake 224 verified noun cells for complete Polish or English.

## v1.11 — roadmap v1.02–v1.11, CORE-first morphology

The project now provides **data-driven generation and analysis of inflected word forms** for a limited PL/EN vocabulary. The shared morphology engine reads paradigms, stems, morphophonological operations and lexical exceptions from JSON. A finite inverse index returns all supported grammatical analyses for a surface word. A CORE-linked dictionary remains the source of meaning for every lexeme; suffixes are never assigned their own invented meaning.

- Modules: `js/core/morphology/{engine,features,operations,compiler}.js`.
- Packages: `data/morphology/{features,pl,en}.json`. An Arabic root-template *morphology fixture* is also provided; Arabic is **not** a sentence translation option.
- Polish/English adapters use generated noun, verb and adjective forms through a compatibility bridge. The old API still works without morphology supplied.
- Inspect forms and their source rules in the **Morphology Inspector** on the static page or offline `index.html`. `fox/lis` and `child/dziecko` demonstrate new dictionary lemmas with no explicit case/number form tables.
- Importer for user-supplied UniMorph-style TSV writes review **staging** only, never directly to the active lexicon. Coverage and compiled finite form tables are available via CLI.

```sh
npm run check:morphology
npm run compile:pl
npm run compile:en
npm run check:release
```

[Full morphology contract, stages and limitations](docs/morphology-v1.11.md).
**Coverage is limited to declared inflectional cells in the curated PL/EN dictionaries; the system is not a general-purpose morphological analyzer for every Polish/English word.** Function words, certain modifiers and grammatical constructions still rely on separate existing rules. Arabic only proves one root-template mechanism.

## v1.01 — canonical lexical CORE (Polish and English first)

**Every canonical Polish and English lexeme has one or more `LexicalSense`
entries with validated, typed `CoreReference` objects.** This includes nouns,
verbs, adjectives, degree words, quantifiers, matrix predicates and an initial
inventory of grammatical function words. CORE distinguishes semantic concepts,
operators and grammatical functions. `bank` has separate financial and river
meanings, while `that` has different complementizer/relative-marker functions.

The PL/EN data use `lexicalModel: "1.01"`; Turkish retains the v1.0 source format
through a compatibility normalizer. Existing JSON grammatical forms and
controlled translation behavior remain intact; **productive morphology is a
later stage**, not an accomplished feature of v1.01.

CORE is now an actual *wire language*: choose `CORE · JSON` as source/target in
the UI, or translate with `from:'core'` / `to:'core'` in the API. CORE input is
validated Interlingua JSON, not a new natural-language spelling scheme.

```sh
npm run check:lexicon   # all active PL/EN entries must resolve to CORE
npm test                # regression and lexical validation
```

New JS methods: `engine.lookupLexemes({language,lemma})`,
`engine.lexemesForCore({language,coreRef})`, `engine.resolveCoreRef(ref)`.
See [lexical CORE v1.01 specification](docs/lexical-core-v1.01.md).

## v0.6 additions

- **Relative clauses as semantic arguments:** a referent now contains a bounded relative clause with an explicit `gap` (`agent` or `theme`). The gap is identical to the antecedent, **not** a duplicated noun; the shared parser/realizer handles the embedded event frame.
- **Depth-two nested relatives:** English `that/who/which`, Polish `który/która/którego/...`, Polish comma boundaries and agreement are selected by declarative `nounPhrase.relatives` JSON, rather than adding syntax-specific JS to language adapters.
- **Coordination as a semantic operator:** `createCoordination([eventA,eventB])` represents a single conjunction distinct from the sequential multi-event discourse. Connective words are JSON-configured (`and` / `i`).
- **Explicit wide negation:** `createNegation(createCoordination(...))` represents `not(A and B)`, separate from locally negating event A. Controlled text uses `It is not true that` / `Nie jest prawdą, że` to make wide scope visible.
- **Topic hints in composed clauses:** nested semantic roles participate in explicit topic scoring, preserving candidate ambiguity (e.g. `bank` inside a relative clause).
- **Historical v0.6 note:** standalone HTML was once supported for `file://`; it was retired in October 2026. The current UI runs through the local server started by `start.bat`.
- **Backward compatibility:** simple events and qualified referents keep earlier semantic document versions. Lexicon/grammar schema is now v0.6; the feature registry remains v0.3.

Details: [semantics v0.6](docs/semantics-v0.6.md) and [grammar v0.6](docs/grammar-v0.6.md).

## v0.5 additions

- **Qualified semantic referents:** language-neutral adjective properties (`quality.big`, `quality.red`) and recursively nested degree modifiers (`degree.very`), with strict validation and bounded depth.
- **Cardinal and universal nominal quantifiers:** `exact: 2` and `universal` in the supplied dictionaries; they are separate from semantic number and definiteness.
- **Shared nominal interpreter:** `js/core/nominals.js` reads inflected adjective and numeral entries from JSON; neither language adapter contains a new inflection function.
- **Case, gender, animacy and number agreement:** PL examples include `duża dziewczynka`, `duzi chłopcy`, `dwie książki`, `małego chłopca` and negated genitive `wszystkich małych książek`.
- **Configurable NP slot orders:** EN distinguishes `all the dogs` from `the two dogs`, with a lexical article selection rule for `a big apple`; PL has a separate layout.
- **Historical v0.5 note:** a generated `file://` build was supported then; standalone HTML was retired in October 2026. Current UI runs through a local HTTP server.
- **Backward compatibility:** plain single events remain `0.2`, plain discourse remains `0.4`, and any graph containing qualified referents is `0.5`.

See [semantics v0.5](docs/semantics-v0.5.md) and [grammar v0.5](docs/grammar-v0.5.md) for the specific schema and limitations.

## v0.4 additions

- **Validated ontology** with taxonomic `parent`, subtype checking (`isA`), cyclic-parent rejection, typed semantic relations, inherited event frames and argument type restrictions (`js/core/ontology.js`).
- **Polysemy**: one lexeme can represent multiple distinct concepts via `senses[]`; e.g. `bank` as financial institution vs river bank. Ambiguity is explicitly reported and multiple interlingua readings are exposed.
- **Synonymy**: multiple lexemes can realize a single concept; e.g. `dog` and `hound` map to the same `animal.dog` semantic concept. Target realization is deterministic.
- **Context hints**: `context.senses` filters a known semantic reading, while `context.topics` biases candidate ranking using explicit ontology relations. These are not statistical confidence estimates or general word-sense disambiguation.
- **Discourse graphs**: 2–8 ordered events in a single graph, with entity IDs that may explicitly be reused across events. No automatic coreference is assumed from repeated words.
- **UI**: samples for polysemy and two sentences, topic selector, separate display of semantic vs grammatical alternatives, Interlingua inspector.
- Test coverage expanded with ontology integrity, ambiguity, context hints, sense IDs, discourse validation, JSON-only dictionary extensibility, and existing grammar regression tests.

## Architecture

```text
index.html → js/main.js
               |
               v
        js/core/engine.js ──── js/core/ontology.js  ← data/concepts.json
               |                   (taxonomy + typed relations)
               v
       js/core/grammar.js ─── js/core/features.js   ← data/features.json
               |
       js/core/nominals.js (qualified referents)
               |                 (case, number, aspect, ...)
               |        data/{en,pl}.json (lexemes, senses, modifiers, numerals)
               |        data/grammar/{en,pl}.json (declarative rules)
               v
        js/core/interlingua.js
           ↙               ↘
  event v0.2/v0.5/v0.6    discourse v0.4/v0.5/v0.6
        relative / coordination / scope v0.6
               |
               v
       target adapter → text + warnings + alternatives
```

| Component | Purpose |
| --- | --- |
| `data/concepts.json` | Shared meaning IDs, event roles, hierarchy, semantic relations |
| `data/{en,pl}.json` | Language-local nouns, verbs, adjectives, degree words, quantifiers and inflected forms |
| `data/grammar/{en,pl}.json` | Noun determiner rules, cases, word order, agreement, verb patterns |
| `data/features.json` | Universal feature dimensions (currently schema v0.3) |
| `js/core/ontology.js` | Validated ontology and semantic queries |
| `js/core/engine.js` | Composition, candidate ranking, translation, multi-event orchestration |
| `js/core/grammar.js` | Generic frame-driven parser/realizer, lexical senses, bounded relative gaps |
| `js/core/nominals.js` | Shared JSON-driven qualified NP parsing and realization |
| `js/core/interlingua.js` | Single event, multi-event discourse, relative clauses and scoped semantic operators |
| `js/languages/{en,pl}.js` | Lightweight adapters using the common interpreter |
| `tests/` | Shared browser/Node grammar contract + Node semantic, UI and HTTP tests |
| `tools/serve.mjs` / `start.bat` | Safe loopback HTTP development server and Windows launcher |

## Try it

**Ambiguous word** — source English:

```text
The girl saw a bank.
```

Default display:

```text
Dziewczynka widziała bank.
```

Semantic alternative:

```text
Dziewczynka widziała brzeg.
```

The `context-topic` UI dropdown can explicitly favor the river/financial reading. Both readings remain distinguishable in Interlingua, including their source lexical sense IDs.

**Two ordered events:**

```text
The girl saw the dog. The boy gave the girl an apple.
→ Dziewczynka widziała psa. Chłopiec dał dziewczynce jabłko.
```

Output Interlingua is a `discourse` with distinct event and entity IDs and `precedes` relations.

**Qualified referents:**

```text
All the big boys saw two small books.
→ Wszyscy duzi chłopcy widzieli dwie małe książki.
```

The Interlingua inspector shows adjective concepts, recursive degree modifiers, exact/universal quantifiers and `0.5` graph versions. Use the **Przymiotniki i liczebniki** sample in the UI.

**Programmatic use:**

```js
const readings = engine.analyzeCandidates({text: 'The girl saw a bank.', from: 'en'});
const result = engine.translate({
  text: 'The girl saw a bank.', from: 'en', to: 'pl',
  context: { senses: { theme: 'place.riverbank' } }
});
// result.text === 'Dziewczynka widziała brzeg.'
// result.semanticAlternatives are alternative meanings
// result.alternatives are target morphology/determiner alternatives
```

`analyze()` deliberately returns only the preferred candidate for backwards compatibility. Applications requiring uncertainty must use `analyzeCandidates()` and inspect `semanticAlternatives` from `translate()`.

## Limitations

Controlled sentences only, limited vocabulary, tense/polarity, prenominal adjectives and a small set of quantifiers. No pronoun anaphora, idioms, general complement clauses, arbitrary nested predicates, general-purpose numeral rules, complete logical quantifier scoping, broad contextual disambiguation, language-specific referential tracking, or complete Polish/English morphology. Subject/object-gap relatives are restricted to depth two, text recognition supports one relative per NP, and conjunction parsing is top-level only. Topic matching uses explicit relationships, not machine learning. More than 16 semantic candidate readings are pruned; **do not treat the displayed alternatives as exhaustive**. For multi-event discourse, target surface alternatives are not combined exponentially. Repeated nouns in different sentences do **not** imply identity; sharing must be explicit in the graph.

Where English does not carry Polish aspect or Polish does not specify English article definiteness, the engine **preserves unknown semantic features** and emits display-default warnings/alternatives. The system does not fill missing meaning just to produce a sentence.

## Next focus

Develop sentence complements and additional subordination types, richer typed semantic roles, explicit quantifier scope and a third language family as a typological stress test. Preserve ambiguity rather than guessing missing grammar features.

### Small-batch F2: governed-preposition WH (source code)

The controlled F2 grammar supports `What does the girl look at?` ↔ `Na co patrzy dziewczynka?`, including selected past, negated, and `can` questions, while retaining the semantic `targetRole: theme` gap. Governed prepositions are explicit frame metadata rather than sentence pair templates. See `tests/prepositional-wh-v1.21.test.js`.

### Microbatch E1 — explicit discourse coreference validation

Core source filters polysemous sentence interpretations against opt-in `context.coreference` constraints **before** selecting the bounded candidate beam. Incorrect role links return `INVALID_COREFERENCE` with source/target identifiers rather than discarding an entire valid analysis. The UI does not currently expose this option. See [E1 contract](docs/context-coreference-e1.md).

### E2a — bounded anaphoric subject pronouns (source only)

Controlled two-sentence PL/EN analysis accepts a second-sentence subject pronoun `he/she` or `on/ona` only when **exactly one** semantically compatible `person.boy` or `person.girl` referent occurs in the first event. The CORE discourse shares the exact entity ID, and unsupported or ambiguous references fail explicitly with `UNRESOLVED_ANAPHORA` or `AMBIGUOUS_ANAPHORA`. Target text currently **repeats the noun phrase**, with a warning; generating a target pronoun belongs to E2b. The UI does not currently expose this path. [Contract and limitations](docs/anaphora-e2a.md).

### E2b — safe target-language pronouns (opt-in)

The engine accepts `pronounRealization: 'safe'` for `translate()` and `realize()` to generate a known `she/he` or `ona/on` only when two consecutive INTER events explicitly share one unambiguous participant. The default remains `'repeat'` and preserves legacy noun repetition. Ambiguous antecedents fall back safely to a noun phrase with a warning; `to:'core'` leaves CORE JSON unchanged. Scope and tests: [E2b contract](docs/anaphora-e2b.md). The offline GUI is owned separately.

### E3 — controlled 3–8-sentence anaphora

The engine now tracks explicitly or pronoun-linked identities across up to eight independent event sentences in one call. An earlier entity is reused only when the subject pronoun is unambiguous across prior *distinct* entities; repeated references to one already-linked entity remain one candidate. `AMBIGUOUS_ANAPHORA` and `UNRESOLVED_ANAPHORA` remain explicit. Optional `pronounRealization:'safe'` also supports later sentences; default noun repetition and legacy CORE remain compatible. [E3 technical contract](docs/anaphora-e3.md). GUI integration remains separate.

### E4 — explicit in-memory ConversationContext (CPU/offline)

The engine offers `new ConversationContext(engine,{maxEvents:8})` from `js/core/conversation.js`. Each `translate({text,from,to,...})` call accepts one controlled event sentence, resolves an unambiguous source pronoun against earlier semantic roles, and commits a CORE event only after target realization succeeds. Use `snapshot()` and `reset()` to inspect or clear session state; no persistence, inferred identities, or LLM. Ambiguous meaning requires explicit disambiguation, and memory limits fail without silently evicting events. [E4 contract](docs/conversation-e4.md). UI is maintained by another agent.

### F3 — more compositional multiword predicate meanings

Three new separate INTER meanings and PL/EN lexical realizations: `look for/szukać` (`event.search`), `listen to/słuchać` (`event.auditory_attention`) and `wait for/czekać na` (`event.wait_for_entity`). Polish genitive vs preposition-governed accusative remain language-local grammar rules; controlled WH questions, negation and selected ability modal questions use existing compositional adapters rather than sentence-pair templates. Productive bindings for these five verb pairs (plus earlier `look at` / `pick up`) are now present in the morphology packages; [F3b morphology gold](docs/multiword-morphology-f3.md) covers 55 curated forms and inverse checks. Standalone GUI synchronization has been retired; the UI runs through local HTTP. [F3 technical contract](docs/multiword-f3.md).


### G1a — CI workflow and coverage inventory audit

The historical G1a GitHub Actions workflow targeted `main`, `core/**`, PRs and manual dispatch, separating Node tests, lexical audits, standalone parity and the release gate. The A1 structural inventory also counted PL/EN modal lexemes and checked CORE references. Its `startup_failure` was later fixed; hosted full release runs passed. Standalone parity has since been retired. See [G1 audit](docs/g1-ci-audit.md).

### F3b — productive inflection of multiword verbs (source checkpoint)

The PL/EN morphology engine now supports `appendStem` to attach a particle **after** inflecting the verb head. This adds bindings for 10 existing verb lexemes (five semantic pairs), including `looks for` and `czekała na`. [F3b detailed contract](docs/multiword-morphology-f3.md) and `npm run check:gold-multiword` cover 55 independent gold cells; **6/6 groups passed isolated JS tests**, not the complete Node suite. CI `startup_failure` and offline GUI parity remain open. No GUI changes here.
